## Final release gates

- `bun run build:ts`: passed, including generated Alhena and Vega SSR production assets.
- `bun run typecheck`: passed with TS7 across the root and all four workspaces.
- `bun run lint`: passed with type-aware errors, deny-warnings and unused-disable reporting; no global rules relaxed.
- `bun run format:check`: passed on all matched files through the standard oxfmt CLI.
- `bun run test:unit -- --pool=threads --maxWorkers=1`: 68 tests passed (Antares 33, Vega 23, Atria 11, Alhena 1).
- `bun run test:integration -- --pool=threads --maxWorkers=1`: 20 tests in seven suites passed with real disposable PostgreSQL/PostGIS and S3.
- `bun run test:e2e`: 15 browser tests passed in development and production. The production-only static-cache test is intentionally skipped in development; it passed in production.
- Additional current state scenarios passed in both builds for real mouse block reordering, keyboard move controls, sanitized fullscreen/language preview, independent banner editing, PNG through SDK/S3, admin/public image reads, tablet editing, and phone-width public SSR without JavaScript.
- `build:storybook`: passed, including triggered, controlled and fullscreen dialog states.
- Root Compose/dev and affected Antares/Vega definitions validated with the root environment file. No Minecraft EULA was accepted.
- Reviewed migrations applied to the existing local `localhost:5432/helicraft` database. The migrator registered all 10 entries (0000–0009). No schema push or destructive reset was used.
- Archive remained unchanged, and authored code introduced no `any`, unchecked casts, archive runtime imports, cross-application runtime imports, client-visible secrets, or future game-system CRUD.

Historical read comparisons use the exact PostgreSQL revision timestamp rather than a JavaScript Date rounded to milliseconds. Holder closure/opening writes use one transaction timestamp, preventing overlapping historical assignments. The real database scenario verifies the boundary.

Initial restricted-environment worker/connection failures and a transient development module-load failure were resolved or rerun successfully in the working execution environment. They are not outstanding release gaps.
