# Account, state and administration workspaces

Account navigation stays visible throughout account pages, including state drafts. State and company management use their own dedicated sidebars. Public navigation groups world discovery and economic directories instead of listing every directory at the top level. Administration uses the same workspace rhythm with a permission-filtered sidebar, compact actions, bounded forms and overview cards. Empty, loading and failed lists must explain the next useful action. Administrative player/audit filters use responsive grids; editorial lists explain draft/publication workflows. Audit metadata expands per record rather than dominating the table.

Do not use a rounded side border or inset vertical stripe to identify active navigation or decorate state/profile panels. Use surface fill, font weight, spacing and an explicit current-page marker. State pages have no colored top stripe. Prefer a consistent grid for office cards, aligned content and natural-height actions; never stretch buttons or short text to fill a viewport.

Directory and player-profile state items use Atria StateCard with the state's color. A tinted surface carries identity while text retains theme colors. State detail mixes small proportions of the chosen color into backgrounds; its primary text accent mixes with the theme text instead of using arbitrary raw colors for reading. Raw state color is suitable for decorative marks only.

Constitutions have a separate public SSR document at `/states/:slug/constitution`, retaining the revision-bound, Antares-sanitized document. Pending private records use the bounded fullscreen dialog. Citizen lists render ten people per page with ordinary GET links preserving the current query and language. Pagination works without JavaScript, and malformed or out-of-range page numbers resolve to a valid page. Membership start time and immutable UUID provide deterministic order.

`/app/states/:id/manage` is a protected state workspace with its own section menu: overview/onboarding, citizens, government/offices, appointments, state reforms, authorized financial/institution tools, diplomacy, citizenship and revision history. The overview links to the public identity/constitution; missing diplomatic procedures remain visible with an explanation. All citizens can prepare proposals. Authority to approve/publish is rechecked by Antares against current offices and decision policies. Governance/constitution reforms support identity, office definitions and constitutional content; no independent future law CRUD is implied. Existing offices retain their immutable initial roster in reform drafts. Current holders change through separate office proposals, never by rewriting that roster. New offices may initially select active citizens; state creation still selects founders.

Office proposals join the published appointment/removal policy with the office appointment or vacancy rule. A replacement also requires the removal policy. Required citizen/council decisions use ordinary single-question Voting records. Current office approvals, successful closed votes and any reasoned administrative manual review are required together. Proposals pin the governance revision and vacancy state; stale proposals must be replaced. Applying a decision closes and opens holder intervals atomically. The appointments section explains requirements and gives only currently authorized approval actions.

Voluntary departure refuses any current office holder, including optional offices, until all appointments end through their current procedures. It closes membership at one transaction timestamp and records an audit event. Published revisions, founders and frozen electorates remain historical records.

# Shared controls

Atria FieldHelp supplies field explanations through a hover/tap popover. Hover opens a transient explanation; click pins it until a second click, outside press or Escape. Keyboard opening remains available. FormField accepts `help` in addition to always-visible `hint`; give examples and explain denominators or scope for voting parameters. An information button must have a distinct accessible name from the input label. Standalone company explanations use `showLabel` to keep their subject visible beside the icon; field-specific help stays attached to its label.

Atria `Form` accepts a typed `FormModel` instance with default values, a Standard Schema validator and field descriptors; it creates the TanStack Form instance automatically. Complex editors may use `useFormModel` and pass the instance to `Form`. One content-language selector controls generated localized fields and nested `LocalizableTextInput` components throughout the form. Switching languages preserves explicit values and never copies display fallbacks. `FormSection` groups related controls, schema errors appear at the field and in a summary, and submission failures stay visible. Vega supplies its platform locale catalog and localized labels. A standalone `LocalizableTextInput` keeps the primary language visible and reveals other translations together in a disclosure. Editorial/gallery forms preserve their existing original-language and translation contracts.

PlayerNickname, StateName and CompanyName link directly to public entities and expose short hover/focus previews. Nickname and state facts are fetched from their public endpoints only when needed, without credentials. State previews show the current public description and citizen/office counts; unavailable public records retain a direct link without private data. Previews never expose private account fields. The preview uses a collision-aware tooltip portal, supports Escape dismissal and stays hoverable. Long descriptions are visually clipped to a compact summary; the linked page contains the full text. The link's accessible name remains the actual entity name; preview text supplies a description. Use non-link identities inside existing selection buttons or card links. Company identities use their square published logo or a decorative color mark.

Storybook documents Form, FieldHelp, LocalizableTextInput, PlayerNickname, StateName, CompanyName, StateCard and Dialog, including many languages, very light state colors and fullscreen reading. Respect reduced motion and keyboard navigation.

Taxation and diplomacy extend the existing state section menu. Tax offices, localized law amendments/repeal, immutable decisions, receipts and foreign-currency treasury totals remain protected. Treaty drafting uses partner → supported type/text → terms → review, then independently submitted decisions from both states. Wallet confirmation displays the server quote and exact debit before payment; history can load the taxpayer's saved legal calculation. Public tax-office/law/treaty pages use cookie-free SSR. Administration reuses institution review controls for tax-office ratification, suspension/restoration and immutable reasons.

See [the 2026-10-18 verification record](../verification/workspaces-2026-10-18.md) for the delivered workspace changes and their verification status at that date. Server identity follows [the central settings contract](../architecture/site-settings.md).

## Company management and approvals

`/app/companies/:id` is a dedicated protected management panel. Its section links use client routing and retain the company projection while loading or refreshing section data. The overview shows actual issued shares, shareholders, office holders and links to decisions. Company pages tint surfaces from their approved color while retaining theme text contrast.

`/app/notifications` is an actionable approval inbox, not an external message delivery system. It exposes only requests the signed-in player can currently consent to, review, approve or execute through the actual state or company procedures. Formation consent progress uses the same exact saved terms and evidence as registration. State applications link to a focused review page, and saved state decisions link directly to their approvals and execution page. Proposal, approval/voting and execution remain distinct domain steps; single-office decisions may already execute atomically.

Company presets show an explanation and require an explicit apply action and replacement confirmation. State company requests and decisions precede the expandable registration-policy settings. Poll editors share one content-language control, separate content from schedule/publication settings and keep secondary block actions together.

## Shared working screens

Atria `WorkspaceNavigation` is shared by account, administration, company and state menus. On widths below 60rem a button shows both the menu name and the current section; expanding it reveals the ordinary capability-filtered links. Selecting a link closes the disclosure. Desktop navigation remains visible. Icons come from Lucide, and controls retain readable labels or explicit accessible names.

`WorkspaceContent` provides bounded controls, natural-height content and consistent spacing in protected screens. `PageHeader` groups a title, explanation and actions. `ActionPanel` reveals creation controls without unmounting their drafts; it is used for monetary decisions, payments, branches, subsidiary formation, office changes, share issuance and charter amendments. Keep one disclosure per action, rather than nesting a second creation disclosure inside it. Dialogs retain their close control in a sticky header; fullscreen editor actions remain available at the bottom while the document scrolls.

The account overview prioritizes actual workspaces and the approval inbox, with profile/settings actions grouped below. Tax records use keyboard-operated Laws, Decisions and Assessments/receipts tabs; law editing opens a focused dialog and returns to the selected tab. Monetary, taxation, diplomacy and currency-exchange sections share the same directive list. Public content still uses its cookie-free SSR contracts.

## Poll editing and participation

The poll constructor uses Questions → Settings → Review. Stages preserve the same typed form and explicit translations. Switching between choice voting and surveys retains each format's questions for the lifetime of the editor. Publication appears only in Review, with actionable missing-content/date warnings; saving a draft remains available throughout. The default schedule lasts 24 hours. The content-language selector appears only while editing questions. Entering Review must never publish the poll as a side effect of the Continue button changing into Publish.

Preview controls are interactive and do not submit responses. Single-answer questions use native radio groups; multiple-answer questions use checkboxes. Option removal and question movement use labelled Lucide controls. Voting directories show compact summaries and direct links rather than every ballot and response list at once. Administration opens an individual vote at `/admin/votings?votingId=:id`; participant links use `/app/votings/:id`. Existing authorization, immutable published questions, electorate freezing, autosave serialization and response visibility remain owned by Antares.

The interaction choices follow [GOV.UK check answers](https://design-system.service.gov.uk/patterns/check-answers/) and [question pages](https://design-system.service.gov.uk/patterns/question-pages/): group related inputs, preserve answers between stages, allow review before an irreversible publication and keep actions explicit. The archived Vesper constructor was consulted as a read-only reference for separated settings, block actions and publication.

## Persistent layouts and staged tasks

`WorkspaceLayout` in Atria owns state/company accents, readable action/focus colors and tinted surface/border tokens. The same context reaches portalled dialogs. Financial and tax cards consume workspace tokens with neutral fallbacks. State tools are grouped beneath **Institutions** in the main menu: the overview explains each authorized tool, while an inner navigation switches bank, currency, monetary policy, issuance, bank finances, treasury, taxation, exchange and company registration. Existing section URLs continue to work, and Antares still rechecks every authority.

State formation/reform and company formation use `WorkflowLayout` with a current stage, direct return to earlier stages and Back/Continue controls. State stages are grouped by identity, people, government and publication; review issues link back to their settings. Private draft names are secondary disclosures. This follows the [W3C guidance on multi-page forms](https://www.w3.org/WAI/tutorials/forms/multi-page/): logical groups, recognizable progress and preserved work.

Internal ordinary anchors receive client navigation after hydration through the shared site layout; router Links retain their normal handling. Modified/external/download/API/fragment/native links retain browser behavior. Root branding and protected route loaders reuse short-lived public data, and the QueryClient has a short freshness interval; authentication and server-side authorization remain rechecked. Editable draft snapshots bypass retained query caching so returning from approvals cannot initialize an editor with an old version; state and company navigation flush their save queues before leaving. Workspace sections retain their shell while lazy tools show local loading feedback. Gallery publication and deletion also navigate through the router. Public SSR anchors and HTML remain available without JavaScript.

State identity, monetary identity, tax documents and company formal charters use model-driven localized field groups. `Form embedded` renders no nested native form; `FormLanguageScope` shares one language across nested state/company Governance controls. Missing translations stay empty and no fallback is persisted by language switching.

Storybook has a task-oriented hierarchy, introductory guidance and semantic-token reference. The [Atria agent guide](../../packages/atria/AGENTS.md) is the maintained acceptance checklist; source stories, public APIs and both package READMEs must agree. Component examples belong beside their source, cross-component examples under Patterns.

Company governance puts the amendment action before a collapsible current charter. Charter editing uses labelled tabs for offices, authority, voting and share transfers. Workspace rows use natural content height, and tabs keep intact labels inside their own horizontal scroll area on narrow screens.
