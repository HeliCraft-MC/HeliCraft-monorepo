# Gallery

Gallery is a separate Antares domain, independent of CMS, game events and skins. Vega uses generated Alhena over the same-origin HTTP API; only Antares accesses PostgreSQL and private S3. Migration `0003_harsh_goliath.sql` creates `gallery_images`. Stable image UUIDs and immutable account UUIDs identify images and ownership. Mutable author/player labels are resolved from identity at read time.

`GET /api/v1/public/gallery` accepts existing page/pageSize conventions and returns bounded items plus a public total in deterministic createdAt/id order. `GET /api/v1/public/gallery/{id}` returns public metadata. Each record contains title, plain-text description, required accessible alt, optional place, optional integer x/y/z plus dimension, participant UUIDs, normalized dimensions and creation/publication time. Storage keys are never returned. Upload immediately publishes; this minimal domain has no draft/private upload or moderation workflow. Deleted records are excluded from every public read, hero and sitemap.

`POST /api/v1/account/gallery` accepts multipart file and a JSON `metadata` string, validates the current session and uses its principal UUID as owner. Existing browser origin/CSRF policy applies. The 10 MiB file limit, 24 million decoded pixel limit, static PNG/JPEG/WebP whitelist and strict decoder prevent disguised files, animation and oversized decode. Sharp rotates, decodes and emits metadata-free WebP: display bounded at 2560px and thumbnail bounded at 800px. Keys use `gallery/<owner UUID>/<image UUID>/{image,thumbnail}.webp`, separate from skins. Both objects are written and read back before the SQL transaction checks active ownership and inserts a public record. A failed storage write returns 503 and never commits an image record.

Images are served by controlled `GET /api/v1/public/gallery/{id}/{image,thumbnail}` endpoints, which check public availability before private S3 access. They return WebP and revalidation caching; storage failures return 503. `DELETE /api/v1/account/gallery/{id}` requires ownership and soft-removes the record. Future private-object lifecycle cleanup can remove unused/deleted blobs; no deleted image remains available through the API. The bucket is never made public.

Vega `/gallery` and `/gallery/:id` are public SSR pages with canonical metadata, semantic tiles, alt text and actual captions/authors/dates. Pagination is ordinary links and works without JavaScript. Failures have an honest unavailable state; unknown IDs return 404. `/app/gallery/new` uses existing account CSR authentication and supports photo preview, title, alt, description, place, optional coordinates and marking the author as present. Object URLs are released. Deletion controls are fetched only after hydration and never add protected account data to public loaders. Public loaders omit session cookies; service worker never caches gallery API or protected forms.

`bun run generate` exports the OpenAPI contract and regenerates Alhena; generated files are not hand-edited. Validation includes decoder/unit tests, SSR/component tests, `bunx --bun playwright test --config playwright.gallery.config.ts` with local gallery fixtures, and the real persistence scenario `bun run --cwd apps/antares test:integration -- tests/gallery.integration.test.ts`. Root Playwright additionally exercises authenticated upload/detail/deletion against disposable PostgreSQL/S3. A Docker daemon is required for persistence tests and root E2E; local smoke fixtures are not evidence of database/S3 integration.

Authenticated `GET /api/v1/account/gallery/players?query=…` searches active player usernames by literal, case-insensitive prefix (2–16 username characters, at most 10 results). Responses contain only UUID and username and use `Cache-Control: no-store`. Vega stores selected UUIDs, displays head avatars, excludes duplicate choices and allows up to 20 tags on upload and caption editing. The upload screen keeps account navigation. Caption and editorial translation forms show one language at a time, preserving all other values during switching and submission.

Photographs can reference up to twenty state relationships (`LOCATION`, `PARTICIPANT`, `RELATED`). UUID/role pairs are stored in `gallery_state_links` with foreign keys and a unique composite key. Owner metadata writes validate active states and commit metadata and relationships together. Public reads resolve current localized names and colors and omit states that are no longer ACTIVE. Relationships are author-supplied editorial metadata, not territorial claims. The photo page presents them as StateName links; the upload and metadata editor provide search and relationship selection.
