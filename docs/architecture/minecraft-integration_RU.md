# Minecraft Integration V1

Реализация единой игровой идентичности в репозитории. Результаты конкретных запусков и оставшаяся приёмка находятся в [verification](../verification/minecraft-integration-2026-10-25_RU.md). [Разработка](../development/minecraft-plugins_RU.md) описывает изолированный стенд, [авторизация игрока](../development/minecraft-authentication_RU.md) — пользовательский сценарий.

## Границы и идентичность

Minecraft использует существующий аккаунт Антареса. Отдельной игровой регистрации, обязательной привязки аккаунтов, парольной БД или runtime LimboAuth нет. Антарес один раз назначает UUID v4; PostgreSQL запрещает его изменение. Этот UUID становится GameProfile ID Velocity и передаётся Paper через modern forwarding. Временный UUID нельзя сначала допустить в мир, а затем исправить.

Существующий username уже соответствует Minecraft: 3–16 ASCII-букв, цифр и подчёркиваний. Нормализация в нижний регистр и уникальность БД исключают регистровые и Unicode-двойники. Каноническое написание приходит из Антареса. Подтверждённое паролем переименование сохраняет UUID, записывает историю и отзывает игровой допуск. Отдельное игровое имя не требуется.

Антарес владеет статусом аккаунта, полномочиями, гражданством и политическим/экономическим состоянием. Денеб передаёт проверенные факты физического мира и не получает полномочия из имени или preset. Список гражданств включает только действующее членство, исключает историческое основательство после выхода и может включать несколько государств. Он не описывает местоположение игрока. Отдельный [Spatial domain](spatial_RU.md) реализует ратифицированные территории и локальный JTS-кэш Денеба; физическая юрисдикция независима от гражданства. Private claims, доказательства физических учреждений, Vault-экономика и World Engine остаются будущей работой.

## Жизненный цикл входа

1. Ригель асинхронно обрабатывает `PreLoginEvent`. Ограниченный сервисный запрос разрешает нормализованное имя, проверяет ACTIVE-аккаунт и создаёт challenge с UUID конкретного соединения. Это определение identity, а не доказательство владения. Неизвестное имя получает адрес регистрации; ошибок с fallback на offline UUID нет.
2. LimboAPI вызывает pre-limbo `GameProfileRequestEvent` Ригеля до создания ожидающего игрока. Ригель назначает UUID аккаунта и каноническое имя, отбрасывая свойства клиентского профиля. `rigel` должен входить в `main.pre-limbo-profile-request-plugins`.
3. `LoginLimboRegisterEvent` регистрирует изолированное виртуальное ожидание. Клиент видит название из настроек, кликабельную одноразовую ссылку Веги, запасной случайный код и срок 120 секунд. Paper ещё не участвует.
4. Владелец открывает ссылку из собственного Minecraft-клиента, при необходимости входит в Вегу, проверяет данные подключения и явно подтверждает или отклоняет запрос. Фрагмент ссылки передаёт тот же код без перепечатывания; ручной ввод также доступен. Имени или ссылки без сессии владельца недостаточно. Другой аккаунт не видит и не подтверждает запрос. Для отклонения знать код не требуется.
5. Ригель опрашивает API с verifier и connection ID. Подтверждение атомарно используется один раз под блокировками аккаунта/challenge. Антарес повторно проверяет ACTIVE, неизменность имени, TTL, proxy binding и браузерную сессию, включая отзыв и оба срока. Создаётся короткий допуск на backend.
6. Только после consumption Ригель покидает limbo. Повторный profile event сохраняет authoritative UUID. `LoginEvent` проверяет локальный допуск; каждый `ServerPreConnectEvent` сначала запрещает переход, сверяет backend и обновляет допуск через Антарес. Forced hosts, `/server` и transfer проходят тот же контроль.
7. Явно асинхронный pre-login Денеба сверяет forwarded UUID/имя с допуском до игры/playerdata. Join подтверждает реальное присутствие в Paper, получает локализованный профиль и все гражданства, показывает приветствие. `/heli`, `/heli status`, `/heli profile` используют эти проверенные данные.
8. Proxy disconnect или Paper quit идемпотентно закрывает точный session ID. Каждое полное переподключение требует нового challenge. Доверия по IP нет.

Состояния: `WAITING_AUTH → APPROVED → CONSUMED`, терминальные `REJECTED`, `EXPIRED`, `DISCONNECTED`. Допуск отличается от реального online. Поздний ответ после отключения не восстанавливает соединение. Один аккаунт не имеет нескольких ожидающих/допущенных соединений; конфликт отклоняется без скрытого вытеснения владельца.

## Секреты, браузер и службы

Challenge содержит случайный UUID, снимок аккаунта/имени, proxy/connection IDs, времена создания/истечения/poll, счётчик ошибок и ссылку на подтвердившую web session. Verifier содержит 32 случайных криптографических байта, код — 8 байтов в виде 16 hex-символов. В БД только SHA-256. Сравнение кода constant-time, максимум пять ошибок; создание и решения ограничены rate limits. Без poll прокси 15 секунд challenge становится недействительным. Это не постоянный игровой токен.

Вега использует существующие HttpOnly/SameSite cookies, точный Origin и Fetch Metadata. Игровые данные доступны только через защищённый CSR и `no-store`; отсутствуют в публичных loaders, профилях, sitemap и service worker. Кабинет показывает только свой UUID/имя, ожидание, текущую lease, последний успешный вход и последние 20 приватных событий. Для ожидающих запросов владельцу также доступны IP/порт подключения, версия протокола и необязательная приблизительная GeoIP-геолокация. Verifier, исходный код подтверждения, хеши кодов и сервисные credentials не возвращаются.

`MINECRAFT_SERVICE_ACTORS` задаёт разные RIGEL/DENEB identities с backend binding и секретными bearer tokens. Ригель создаёт/проверяет/использует только свои challenges и обслуживает свои сессии. Денеб проверяет допуск/профиль и подтверждает/обновляет/закрывает сессии своего backend. Они не получают web admin, credentials, финансовые полномочия или прямой доступ к БД. Internal-запросы с cookies запрещены. Исключение CSRF действует только на точное внутреннее пространство Minecraft с обязательной service authentication; bearer не обходит обычный browser CSRF.

Общий Java-клиент ограничивает connect/request timeout, запрещает redirects, использует минимальные DTO и безопасные ошибки. Удалённый origin требует HTTPS; HTTP разрешён только для loopback/localhost и контейнерного `antares`. Между хостами используйте TLS или шифрованную сеть. Ротация — окружение и перезапуск службы. Нельзя логировать тела запросов, пароли, коды, verifier, tokens и полные аргументы команд. Ошибки service auth/role не раскрывают данные; переходы challenge сохраняют безопасный аудит аккаунта.

Парольная `/login` намеренно недоступна в V1: аргументы могут сохраняться в истории клиента или перехватываться плагинами. Вход через браузер реализует весь процесс без передачи пароля Minecraft. LimboAuth как вторую систему аккаунтов устанавливать нельзя.

## Одноразовые ссылки и данные подключения

Ссылка имеет вид `/app/minecraft#challenge=<UUID>&code=<code>`. Она привязана к существующему challenge; код — то же хешируемое краткоживущее доказательство владения, что и при ручном вводе. Это не токен входа на сайт. GET, предпросмотр ссылки, авторизация на сайте и открытие страницы не подтверждают запрос. Нужен явный POST с сессией владельца, точным Origin и правильным кодом. Ссылка в чужом аккаунте не раскрывает данные целевого подключения. Антарес сохраняет проверки срока, отказа, отмены, одноразового consumption и отзыва аккаунта/сессии.

Фрагмент не отправляется в HTTP-запросах и Referer. Защищённый маршрут исключает его из query-параметра `returnTo`, сохраняя во фрагменте страницы входа; успешная авторизация восстанавливает его на защищённой странице. После явного решения фрагмент удаляется заменой адреса. Полные ссылки нельзя логировать или переносить в query strings, SSR, аналитику, хранилища либо публичные loaders.

Ригель получает необязательные данные из настоящего `InboundConnection`, без доверия HTTP-заголовкам: IP/порт сокета, номер протокола и поддерживаемые им версии. Протокол не удостоверяет ОС, устройство, моды или точную сборку клиента. Миграция `0048_minecraft_connection_details.sql` добавляет nullable JSON в challenge и сохраняет совместимость со старыми запросами. Только scoped RIGEL endpoint создания принимает валидированные данные соединения; собственную GeoIP-геолокацию клиент передать не может. Данные ожидающего подключения возвращаются только владельцу, не публикуются и не доказывают владение аккаунтом. Docker NAT, VPN и прокси могут скрывать исходный IP.

Антарес необязательно читает локальную City MMDB через `maxmind` (`GEOIP_DATABASE_PATH`) без GeoIP HTTP-запросов. Локальные, приватные и зарезервированные адреса обозначаются без поиска. Страна, локализованный город и часовой пояс приблизительны; отсутствие, ошибка базы или неизвестный адрес дают недоступную геолокацию, не ослабляя допуск. Базу предоставляет оператор; автоматического скачивания или коммита нет. См. [настройку разработки](../development/minecraft-plugins_RU.md#optional-local-geoip).

## Присутствие, события и восстановление

Прокси и Paper независимо обновляют lease на 45 секунд каждые десять секунд. Первоначальный допуск имеет deadline для Paper: heartbeat прокси не поддерживает бесконечный online при аварии или отсутствии join Paper. `online` требует реального join, отсутствия end timestamp и обеих живых leases. Production scheduler и чтение кабинета закрывают истёкшие сессии. Недоступность API запрещает новые входы и отключает игроков при ошибке heartbeat. Неуспешную очистку покрывает TTL. Авария не разрешает новый UUID или анонимный допуск.

`minecraft_events` записывает `MINECRAFT_SESSION_STARTED` только при join Paper и `MINECRAFT_SESSION_ENDED` только для ранее вошедшей сессии. Поля: event ID, account UUID, session ID, доверенный source, timestamp, schema version 1, PRIVATE visibility и ограниченная причина. Уникальность session/type предотвращает дубликаты; PostgreSQL запрещает update/delete. События отделены от CMS и раннего примера `world_events`; это небольшая основа будущих событий без отдельной шины.

Переименование, смена пароля, suspension/ban, выход/отзыв web session и административный отзыв закрывают соответствующий допуск. Consumption/heartbeat дополнительно проверяют браузерную сессию и статус. Неоднозначный timeout consumption не повторяется автоматически ради допуска: переподключение ждёт очистки/TTL и получает новый challenge. Сетевые запросы не выполняются на Velocity event loop или каждом movement/block event. Работа с игроком/Bukkit возвращается на главный поток; только явно асинхронный pre-login ожидает ограниченный запрос.

## REST и сохранение

Все маршруты имеют Zod/OpenAPI и generated Альхену:

| Граница             | Маршруты                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Владелец в браузере | `GET /api/v1/account/minecraft`, `POST /api/v1/account/minecraft/challenges/{id}/decision`                                  |
| Challenge Ригеля    | `POST /api/v1/internal/minecraft/challenges`, `POST .../challenges/{id}/{status,consume,cancel}`                            |
| Сессия Ригеля       | `POST /api/v1/internal/minecraft/rigel/{heartbeat,close}`                                                                   |
| Денеб               | `POST /api/v1/internal/minecraft/paper/{admission,profile}`, `POST /api/v1/internal/minecraft/deneb/{join,heartbeat,close}` |

Миграция `0044_uneven_annihilus.sql` добавляет `minecraft_challenges`, `minecraft_sessions`, `minecraft_events`, FK, ограничения состояний/попыток, одну открытую сессию на аккаунт и неизменяемые события. Существующие аккаунты, финансы и миры не переписываются. SQL нужно проверить и применить миграцией; live schema push запрещён. Тестовые БД и миры изолированы и одноразовые.

## Runtime и зависимости

Зафиксированы Velocity 4.2.0 build 30, Paper 26.3 build 223, Java 25 и Gradle 9.1.0. LimboAPI фиксируется commit/version/SHA-256 в `infra/minecraft/limboapi.properties`. Ригель использует MIT API и не включает AGPL-3.0 runtime в JAR. Отдельный runtime сохраняет обязанности upstream по лицензии/исходникам; внутренние классы не копируются. Изменяемый URL `dev-build` защищён обязательным checksum: замена отклоняется и требует проверенного нового pin. Исследование и источники — в [плане](../history/2026-10-25-minecraft-integration-plan_RU.md).

Modern forwarding использует отдельный случайный secret, Paper `online-mode=false`, включённый forwarding и согласованный proxy online-mode. Изолированный Compose публикует только loopback web/proxy, без Paper/PostgreSQL/S3. Forwarding дополняет сетевую изоляцию. Нативный runtime-тест привязывает Paper к loopback и проверяет запрет прямого входа.

Test-only поддерживаемый codec MCProtocolLib 26.3 выполняет native Minecraft 26.3/protocol 777 login/configuration/play и modern forwarding. Текущий harness и Compose не устанавливают ViaVersion/ViaBackwards; прежний lock переводящих адаптеров сохранён только как историческая ссылка. Приёмка человеком в графическом клиенте фиксируется отдельно в [проверках территорий](../verification/territories-2026-10-25_RU.md).

## Language preference

При успешном явном подтверждении в браузере Вега передаёт выбранный язык сайта. Миграция `0047_minecraft_approval_locale.sql` сохраняет nullable-настройку у точного подтверждённого challenge; неверный код и отклонённый запрос её не сохраняют. Допущенная игровая сессия связана с этим challenge. Scoped profile выбирает язык сайта при подтверждении, затем язык Minecraft-клиента и английский для неподдерживаемого языка клиента. Денеб использует проверенный результат для приветствия, профиля и территориальных уведомлений и дожидается проверенного профиля до первого объявления юрисдикции. Смена языка сайта вступает в силу при следующем явном игровом подтверждении. Identity, однократное consumption, Origin и lease-проверки не меняются.
