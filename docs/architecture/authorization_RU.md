# Authorization and administration

PLAYER управляет своим аккаунтом; EDITOR — CMS; MODERATOR — просмотром пользователей, статусами и отзывом сессий; ADMIN/OWNER добавляют управление ролями и просмотр аудита. Интерфейс скрывает недоступные действия, но проверка всегда выполняется API.

Защищённые изменения заново читают статус и роли исполнителя внутри транзакции с общим advisory lock. CMS берёт этот lock до редакционного. ADMIN не управляет ADMIN/OWNER и не назначает OWNER; MODERATOR не управляет равными/старшими. Конкурентные операции сохраняют хотя бы одного ACTIVE OWNER. Аудит, история ников и редакции защищены от UPDATE/DELETE триггерами.

Первый OWNER назначается только CLI существующему активному UUID с явным повторением UUID в --confirm; база должна быть helicraft. Команда не создаёт стандартный пароль и не допускает второго bootstrap-владельца. Дальнейшие роли назначает OWNER в админке. Будущие игровые должности потребуют отдельной модели полномочий.
