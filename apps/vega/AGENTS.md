# Vega agent guide

- Root rules apply. Public pages use SSR without session cookies; `/app` and `/admin` remain protected CSR. Use Alhena for API, Atria for reusable UI and central site settings for display identity. Never put secrets in Vite variables.
- Minecraft UI lives at `/app/minecraft`; [architecture](../../docs/architecture/minecraft-integration.md). Existing account sessions and exact-Origin mutations apply. Show only the owner's attempts. Require an explicit decision and possession of the code from their own game client, supplied by the confirmation link fragment or manual entry. Keep secrets out of query strings, loaders, telemetry and login returnTo parameters; preserve the fragment across login and clear it after a decision. A link/name is never sufficient; never auto-approve on mount/navigation. Do not ask for an account password in this flow.
- Keep loading/error/expiry/rejection states and locale support. Private identity, session/history/challenges never enter public loaders, sitemap, public profiles or service-worker caches. Names may change; UUIDs cannot.
- Root validation: `bun run generate`, `build:ts`, `typecheck`, `lint`, `format:check`, `test:unit`, relevant `test:e2e`, and `test:minecraft` for the full browser/game flow. Existing Atria components need no duplicate Storybook implementation; changes to reusable components must follow Atria's guide.
- Local web: `bun run dev:vega` (terminal logs), or `bun run dev` for API too. Disposable Minecraft staging: `minecraft:up`, web `http://localhost:8096`, game `127.0.0.1:25575`; logs `minecraft:logs vega`; stop `minecraft:down`; disposable-only cleanup `minecraft:clean`. Native-client and translated protocol acceptance remain distinct. Never change user DB/worlds to make a browser test pass.

- `/map` is cookie-free public SSR for registered worlds and published political geometry. Interactive FlatMap loads Leaflet/Geoman lazily in the browser and uses actual squaremap tiles, 512px, CRS.Simple, `[lat,lng]=[-Z/2^maxZoom,X/2^maxZoom]`; never use Mercator, Earth tile services or decorative fake terrain.
- Territory editing belongs to the protected state workspace and requires current CHANGE_TERRITORY authority, repeated by Antares. Keep published shapes read-only; support Polygon/MultiPolygon, holes, explicit save/version conflicts, undo/redo, labelled keyboard coordinate editing, server PostGIS preview and immutable submission. Administrative ratification is a separate protected workflow.
- Reuse Atria FlatMap and form controls; public loaders, sitemap and service-worker caches must never include private drafts, decisions or auth cookies. Verify real renderer tiles, positive/negative coordinate alignment, desktop/mobile/keyboard/error states and the full draw→save→reload→Governance→ratify→public flow in Playwright.
