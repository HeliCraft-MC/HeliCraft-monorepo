# Antares agent guide

- Root rules apply. Antares exclusively owns persistence, immutable account UUIDs and world authority. Domain services stay independent of Hono; typed routes/OpenAPI feed generated Alhena.
- Minecraft implementation: [architecture](../../docs/architecture/minecraft-integration.md). Service actors come from validated `MINECRAFT_SERVICE_ACTORS`: RIGEL may create/poll/consume its connection challenges and maintain its sessions; DENEB may attest/profile/heartbeat sessions for its backend. No general admin authority or user cookies. Internal CSRF exemption is restricted to this exact authenticated route namespace; ordinary browser mutations keep Origin checks.
- Challenges require owner web session and code possession, short TTL, hashed secrets, bounded attempts, single consumption, connection/service binding and user locking. Recheck ACTIVE account and approval session at consumption/heartbeat. Identity changes and session revocation invalidate game access. Never log bodies/secrets or expose another player's challenges.
- Session presence requires actual Paper join and both proxy/Paper leases; private start/end domain events are immutable and idempotent, separate from CMS and `world_events`. Keep retries safe and stale presence expiring.
- Commands from root: `bun run generate`, `build:ts`, `typecheck`, `lint`, `format:check`, `test:unit`, `test:integration`; API-specific `build:antares`, `test:antares`. Review generated SQL and use migrations; no schema push/reset against user persistence. Minecraft contracts: `test:minecraft:contracts`; full runtime: `test:minecraft`.
- Web dev: `bun run infra:up`, `db:migrate`, `dev:antares`; logs in that terminal. Disposable Minecraft staging: `minecraft:up`, `minecraft:logs antares`, `minecraft:down`; `minecraft:clean` removes only that dedicated project's volumes. Do not point it at user database `helicraft`. Native/protocol acceptance is in the development guide. Report unavailable tooling separately.

- Spatial is the PostGIS source of truth: local planar GeoJSON `[X,Z]`, SRID 0, immutable registered backend/Paper UUID/dimension, Overworld-only territory. Reject invalid/self-intersecting/oversized geometry; never silently repair it. Shared edges are legal and exact boundaries are Wilderness.
- Seal a draft with its exact geometry/reason/base/version before the existing `CHANGE_TERRITORY` directive/Voting procedure. State execution creates an application; only separate reasoned admin ratification publishes an immutable revision. Recheck current Governance, proof validity, base revision and positive-area conflicts while holding the world lock. Publication pointer, version and immutable event commit together.
- Spatial snapshots are complete, bounded, integrity-protected and versioned per registered world. Internal spatial APIs require scoped DENEB backend and actual Paper world UUID, reject cookies and other service roles, and never expose drafts. Tile proxy sources are server-only allowlisted origins; fixed registered paths, no redirects/cookie forwarding, bounded streamed PNG responses and no arbitrary URL/path inputs.
