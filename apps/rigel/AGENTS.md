# Rigel agent guide

- Velocity is the sole admission gate. Antares owns account UUID/name, challenge decisions and game sessions. Never add local users, passwords, `/register`, mandatory `/link`, IP-based trust or offline UUID fallback.
- Read [Minecraft architecture](../../docs/architecture/minecraft-integration.md) and [development guide](../../docs/development/minecraft-plugins.md). Identity lookup is not authentication.
- Lifecycle: asynchronous `PreLoginEvent` creates a connection-bound challenge; pre-limbo `GameProfileRequestEvent` sets Antares UUID/name; `LoginLimboRegisterEvent` installs the isolated waiting space; consumption precedes limbo exit; `LoginEvent` and every `ServerPreConnectEvent` enforce admission and backend allowlisting. Never let temporary UUIDs reach Paper. Keep `rigel` in LimboAPI's pre-limbo profile list.
- Pin LimboAPI source/version/checksum in `infra/minecraft/limboapi.properties`. API is MIT, runtime AGPL-3.0 and installed separately; never copy internals or shade runtime. Missing/broken Limbo must fail closed. Do not hot-reload auth plugins.
- HTTP uses the shared Java client, bounded asynchronous requests and `RIGEL_SERVICE_TOKEN`; no user cookies, database or general administrator credential. Require HTTPS outside explicitly local/container origins. Rotate through environment and restart. Never log request bodies, challenges, codes, verifier, tokens or auth command arguments. V1 does not implement password `/login`.
- Disconnect/shutdown cancels waiting challenges and closes admitted sessions. Late responses must not revive a closed connection. Never retry ambiguous consumption automatically. Heartbeat failures disconnect; leases cover crashes.
- Root commands: `bun run build:rigel`, `bun run test:rigel`, `bun run lint:java`, `bun run format:check:java`; shared client checks: `./gradlew :minecraft-client:build`. `dev:rigel` only rebuilds; restart the proxy to install a new JAR.
- Isolated staging: `bun run minecraft:up`; shutdown `minecraft:down`; inspect `bun run minecraft:logs rigel`; remove only disposable volumes with `minecraft:clean`. No user DB/worlds. Test EULA is automatically accepted under the owner's explicit authorization.
- Required integration checks: `bun run test:minecraft:contracts`, `bun run test:minecraft`. A JAR build is not runtime verification. Test unknown/blocked accounts, owner/code/Origin, expiry/replay/disconnect, backend failure, transfers/forced hosts and stable UUID in Paper. The protocol harness uses test-only version translation; separately check a native client as documented.
- Diagnose startup logs first: expected Velocity/Limbo versions, `Rigel ready:`, no invalid forced hosts, correct token/API origin, pre-limbo config and forwarding secret. Keep Paper private; modern forwarding does not replace network isolation. Report absent Docker/browser/Java separately from regressions.
