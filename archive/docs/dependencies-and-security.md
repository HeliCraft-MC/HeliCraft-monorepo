# Зависимости и безопасность

Каждое приложение имеет собственные `package.json` и `bun.lock`. Для lock-файлов с версионными `overrides` нужен Bun 1.4.2 или новее. Текущая установка воспроизводится через `bun install --frozen-lockfile` внутри каталога приложения.

На 28 сентября 2026 года `bun audit` не находит уязвимостей Vesper; в Teapot остаётся одно предупреждение умеренной тяжести для `esbuild@0.18.20`. Его тянет `@esbuild-kit/core-utils` через `drizzle-kit`; совместимой исправленной версии в этой ветке нет. Проверяйте обновления `drizzle-kit` и его загрузчика, затем пересчитывайте аудит. Подмена `esbuild` на другую ветку без проверки инструментов миграции может сломать команды работы с БД.

GitHub [документирует поддержку](https://docs.github.com/en/code-security/reference/supply-chain-security/supported-ecosystems-and-repositories) текстового `bun.lock`, но его Dependabot updater на эту дату [не обрабатывает формат `lockfileVersion: 3`](https://github.com/dependabot/dependabot-core/pull/16071), который Bun создаёт для версионных `overrides`. Поэтому число alerts на GitHub может не совпадать с локальным аудитом и автоматическое обновление lock-файла может не работать до обновления Dependabot. Запускайте аудит локально или в CI; не считайте исчезновение alerts доказательством исправления.

## Обновление

```bash
cd apps/vesper  # затем повторить в apps/teapot
bun outdated
bun update
bun audit
bun run build
```

Для обновления прямых зависимостей через мажорные версии используйте `bun update --latest`, затем проверяйте сборку и поведение. `bun audit` сверяет версии из lock-файла с npm advisory API и требует сети. Оставшиеся предупреждения нужно оценивать по конкретной цепочке зависимостей и исправленной версии; некоторые пакеты используются только при разработке, но это не отменяет проверки.

Не добавляйте уязвимый транзитивный пакет в прямые зависимости ради исчезновения предупреждения: это не заменяет обновление вложенной копии. Принудительные `overrides` допустимы только с проверкой совместимости. По умолчанию не игнорируйте advisories и не снимайте security alerts.

## Эксплуатация

- Секрет JWT и пароли БД задавайте через окружение и не коммитьте `.env`.
- Держите `/dev/make-admin` выключенным; флаг включайте только в локальной среде.
- Используйте HTTPS для refresh cookie и проверяйте фактическую пересылку `Set-Cookie` через прокси Vesper.
- Проверяйте OpenAPI и авторизацию при изменении маршрутов; наличие middleware не заменяет проверки прав внутри операции.
