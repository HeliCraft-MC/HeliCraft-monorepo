# Архитектура

## Приложения

Vesper (`apps/vesper`) — Nuxt 4 на Vue 3. Он показывает страницы, хранит состояние интерфейса и отправляет HTTP-запросы. Teapot (`apps/teapot`) — Nitro API на Bun. Он проверяет права, выполняет операции и единственный подключается к базам. Общего пакета бизнес-логики нет; контракты передаются по REST.

Coming Soon (`apps/soon`) — независимая страница-заглушка на встроенном HTTP-модуле Node.js. Она повторяет тёмную палитру сайта, загружает Press Start 2P из Google Fonts и хранит собственные копии логотипа и фоновых скриншотов Vesper, чтобы собираться из своего Docker context.

```text
Браузер → Vesper :3020 → /distant-api/** → Teapot :3000 → MySQL / SQLite
                         /plan-api/**    → аналитический сервис
Браузер → Coming Soon :3080 (самостоятельная страница)
```

Прокси задаются в `apps/vesper/nuxt.config.ts`. URL Teapot берётся из `NUXT_PUBLIC_BACKEND_URL`, URL аналитики — из `NUXT_PLAN_UPSTREAM_URL`. Изменение этих значений для собранного приложения требует новой сборки.

## Карта кода

| Область | Vesper | Teapot |
| --- | --- | --- |
| Входные точки | `app/pages`, `server/api` | `server/routes` |
| Прикладная логика | `app/composables`, `app/utils` | `server/utils`, `server/db/repos` |
| Типы | `app/types` | `server/interfaces`, схемы Drizzle в `server/db` |
| Состояние/подключения | `app/plugins`, Nuxt state | `server/plugins` |
| Доступ | `app/middleware` | `server/middleware/auth.ts` |

Основные API-направления: `auth`, `user`, `gallery`, `forms`, `banlist`, `state`, `cities`, `alliances`, `wars`, `history`, `order`, `warrant`. Часть функций государств отключена на сайте по умолчанию; наличие маршрута API само по себе не подтверждает готовность функции к использованию.

## Границы изменений

Не импортируйте код одного приложения напрямую в другое. Новые поля и маршруты сначала документируйте как контракт, затем проверяйте потребителей в Vesper и обработчики в Teapot. Для изменений авторизации проверяйте путь через прокси, cookie и серверный рендеринг. Для изменений схемы данных проверяйте целевую базу: разные схемы MySQL обслуживаются разными подключениями.

Teapot предполагается в будущем перенести на Go. Поэтому держите обработчики короткими, бизнес-логику и доступ к данным отдельными, а HTTP DTO явными.
