# API и авторизация

## Путь запроса

Vesper обращается к Teapot через собственный путь `/distant-api/**`; Nuxt проксирует его на адрес из `NUXT_PUBLIC_BACKEND_URL`. Дополнительный `/plan-api/**` ведёт к внешнему сервису аналитики. API-контракт Teapot описан метаданными маршрутов и доступен по `/_openapi.json` и `/_scalar` при запущенном сервере.

## Сессия

1. `POST /auth/login` или `POST /auth/register` возвращает `accessToken`, `uuid`, `nickname` и устанавливает `refreshToken` в HttpOnly cookie.
2. Vesper хранит access token в Nuxt state, `uuid` — в cookie `auth:uuid`; `useAuthSystem` управляет входом, обновлением и выходом.
3. Защищённые запросы передают `Authorization: Bearer <accessToken>`. `server/middleware/auth.ts` проверяет токен и добавляет UUID в контекст запроса.
4. `POST /auth/refresh` читает HttpOnly cookie и UUID из тела запроса, выдаёт новый access token и обновляет cookie. `POST /auth/logout` удаляет cookie.

Для изменяющих запросов в областях государств, войн, союзов, отношений, указов и ордеров Teapot берёт UUID действующего лица из проверенного токена. Переданные клиентом `adminUuid`, `playerUuid`, `requesterUuid` и подобные поля больше не определяют права или автора операции. Историю может создавать, изменять и удалять только администратор; `created_by_uuid` и `deleted_by_uuid` записываются из сессии.

`auth:uuid` не является доказательством входа: он только помогает попытаться восстановить сессию. Учитывайте SSR и прокси при правках cookie. Значение `secure: true` у refresh cookie требует HTTPS при обычном внешнем развёртывании; локальная работа зависит от поведения браузера для `localhost`.

На сервере задавайте уникальный `NITRO_JWT_SECRET`. Не размещайте токены или пароли в публичной конфигурации Nuxt. Маршрут `/dev/make-admin` имеет дополнительный явный флаг `NITRO_ENABLE_DEV_ADMIN=true` и доступен только в режиме разработки.

## Изменение контракта

Для нового или изменённого маршрута обновите `defineRouteMeta`, уточните DTO в Teapot и проверьте вызывающие места и типы в Vesper. Если меняется ответ или статус ошибки, проверьте вход, SSR, обработку 401 и соответствующий экран.
